# Camera menus / UI・UX v0.1

## 目的と実装

子供や小さい文字が読みづらい人が、スマホを置いたままゲームを選び、開始し、再挑戦・次のゲームへ進める共通メニュー。タッチ・キーボード操作も維持する。

- FEEDの装飾番号・小さなキャプションを削除。「あそぶ」「前のゲーム」「次のゲーム」を大きく、日本語で表示する。
- 39ゲームの開始画面を `src/platform/launchOverview.js` で整理。画像・ゲーム名・短い説明・主要操作を先に置き、キャラクター・難易度・CREATOR等の既存設定は折りたたむ。ゲームごとのDOM、データ属性、設定ハンドラは保持する。
- 主要ボタンは高さ64px、補助操作52px。通常の説明・補助操作は16px以上。詳細な遊び方・素材・プライバシーは既存のダイアログから確認できる。
- 通常結果の「もう一度」「次のゲーム」を先に表示する。MARU MAGICは結果でも描画位置・スクロール位置を保ち、再挑戦・次のゲームとカメラUIを画面下に固定する。短い画面・拡大表示では補足内容のスクロールを許容し、主要操作を優先する。
- 過去に読み込まれたゲームのCSSが共通メニューに影響する問題を、`platform-menu` の色・配置の分離で防ぐ。ゲーム本体の描画・ルールは各ゲームが所有する。

## Camera UI

PR #8の依存ゼロの `DwellTarget` / `AirSwipe` / `CameraUiInput` を取り込み、FEED専用だったコントローラーをシェル所有の `src/cameraUi/controller.js` に拡張した。

- 初期値OFF。手で操作ボタンを明示的に押すまで、FEEDから認識ライブラリ・モデル・カメラを読み込まない。
- 650msの安定したホールドで決定。指カーソルと進捗リングを表示する。
- FEEDでは左24%で上下のフリック。必要距離・サンプル数・速度・停止による再アームで、1ジェスチャー1カードに限定する。
- 共通開始画面、結果画面、戻る操作にも対応。シェア・保存・撮影モードの設定等は手による決定の対象に含めない。
- 手を見失う・映像が止まる・対象から外れる・画面遷移・リサイズ・フォーカス喪失でホールドを解除する。
- プレイ開始前にメニュー用のカメラとモデルを解放。通常の結果画面では、同じページ内のON設定を引き継いで認識を再開する。ページを読み直すとOFFに戻る。
- MARU MAGICは連続召喚型で結果中もゲームのカメラを使う。その結果中は既存の認識フレームを共有し、追加のカメラ・モデルを開始しない。共有メニューON時のリトライも700msを維持し、従来の判定との二重発火を防ぐ。OFF時の従来の指リトライは維持する。
- 固定メニューからのMARU再挑戦は、直前の指位置をゲーム座標で保持し、その位置を離れてから次の円を準備する。画面全体のメニュー座標と、カメラを正方形に切り抜いたゲーム座標を混同しない。
- カメラ許可拒否・開始失敗でもタッチ操作は継続できる。遅れて許可されたカメラも、退出済みなら解放する。

## 検証

`npm test` と `npm run build` に加え、以下のPlaywright CLIスクリプトを使う。

```text
playwright-cli open http://127.0.0.1:5173/
playwright-cli run-code --filename scripts/qa/accessible-ui.js
playwright-cli run-code --filename scripts/qa/camera-ui-interaction.js
```

`accessible-ui.js`: 360×640 / 390×844 / 1440×900、全39ゲームの開始ボタンとFEEDの高さ、ゲーム切替後のコントラスト、画像の読み込み、既存設定・言語切替・タッチ操作を249項目で検証。

`camera-ui-interaction.js`: カメラと認識を代替し、明示的ON、AIR TAP、AIR SCROLL、AIR RETRY、プレイ中の解放、結果からの再開、MARUの認識共有、通常結果のRETRY/NEXT、OFF・拒否・遅い許可応答を検証する。MARUは360×668で描画・スクロール位置の維持、スクロール後も全結果操作が見えること、再挑戦位置では準備されず別の開始位置で準備されることも確認する。実機の認識精度を保証するテストではない。

ローカル検証結果：`npm test` **654 / 654成功**、`npm run build` 成功、両ブラウザQAスクリプト成功。ビルドには既存の大きなゲームチャンクに関する警告が残る。

実機フィードバック後の固定メニュー修正は、影響する回帰テスト58項目、全ゲームのレイアウト249項目、合成入力26項目とビルドが成功。合成カメラはMARU区間で実機と同じ1280×720を使い、画面全体とゲームの切り抜きの座標差も含めて再挑戦後の開始位置を確認した。

### A401OP実機確認 — 2026-10-09

ユーザーがUSBで接続。`adb reverse tcp:5173 tcp:5173`でローカルの開発版を端末Chromeに開き、CDP経由で表示とカメラ状態を確認した。本番公開版への反映ではない。

- Android 15、1080×2412 / density 480。Chromeの表示幅360 CSS px、表示高668〜724px。FEEDに横スクロールなし。開始ボタンは画面内。
- Secure Context / MediaDevicesを利用可能。実際の前面カメラ1280×720・設定30fpsが起動し、ライブ映像と手認識モデルの起動を確認。音声トラックなし。カメラ画像の保存は行わない。
- ユーザーから「結果のもう一度が上に大きく出て、タップかスクロールが必要」とフィードバック。結果時の先頭スクロール・ゲーム上への操作追加を廃止し、固定メニューへ修正。
- 修正版についてユーザーが **「その場で指で再挑戦できた」** と確認。これは同じ端末でのMARU再挑戦の確認であり、全ゲーム・全操作の実機検証ではない。

### 実機で残る確認

- 初回ONで人差し指のカーソルが出る。カメラを拒否してもタッチで遊べる。
- 画面に合わせて指を動かし、PLAYから開始まで進む。左側の上下動は1回につき1ゲームだけ切り替わる。
- MARU MAGICをカメラで召喚し、「もう一度」「次のゲーム」を選ぶ。カメラの取り直しによる待ち時間や二重リトライがない。
- 通常の時間制限付きゲームを遊び、終了後に「もう一度」「次のゲーム」を指で選ぶ。
- ゲーム中にボタン操作が発火しない。タブを隠して戻ったときに古いホールドが続かない。
- 文字サイズ・狙いやすさ・ホールド時間・誤決定の少なさを、子供や小さい文字が見づらい人に確認してもらう。
