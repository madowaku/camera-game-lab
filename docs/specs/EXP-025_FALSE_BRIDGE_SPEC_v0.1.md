# EXP-025 FALSE BRIDGE
**遠近法で現実をパズル部品にする / Prototype Spec v0.1**

## ひとことで

**身の回りの物をカメラ越しに位置・角度・大きさを合わせ、画面内の欠けた世界を完成させる遠近法パズル。**

画面には、途中で切れた橋がある。

プレイヤーはアウトカメラを動かし、現実の鉛筆や箸などを画面内へ持ってくる。

ちょうど橋の隙間に重ねると、

**LOCK!**

鉛筆が巨大な橋としてゲーム世界へ固定され、キャラクターが渡っていく。

重要なのは、

> **それが鉛筆かどうかではない。\
> 画面の中で「橋に見える位置」にあるかどうか。**

---

# このEXPで検証したいこと

最優先で確認するのは、

> **「現実の物が、一瞬だけ別の物に見える」こと自体が気持ちいいか？**

さらに、

> **スマホを前後左右へ動かして遠近法を合わせる行為が、パズル操作として成立するか？**

ここが通れば、

**現実遠近法パズル**

という独立した鉱脈になる。

---

# 基本構成

プレイヤー：

**1人**

カメラ：

**アウトカメラ**

入力：

- スマホを動かす
- 現実の物を動かす
- LOCKボタンを押す

1問：

**10〜30秒程度**

MVP：

**5問**

---

# 基本ゲームフロー

## 1. PROBLEM

アウトカメラ映像上にゲーム世界を重ねる。

例：

```text
CLIFF        CLIFF
█████        █████
    \        /
     \      /
      ??????
```

中央に橋がない。

小さなキャラクターが左側で待っている。

表示：

**MAKE A BRIDGE**

---

## 2. FIND

プレイヤーは身の回りを見る。

鉛筆。

箸。

定規。

ストロー。

指。

細長い物なら何でも候補になる。

ゲーム側は、

**「鉛筆を探してください」**

とは言わない。

---

## 3. ALIGN

スマホまたは物体を動かして、

画面内のガイドへ合わせる。

対象物がガイドを十分埋めると、

ガイドが反応。

**ALMOST**

さらに位置・角度・長さが合うと、

**LOCK READY**

---

## 4. LOCK

プレイヤーがタップ。

一瞬カメラ映像を静止、または対象領域だけスナップショット。

現実の物がゲーム世界へ固定される。

**LOCK!**

キャラクターが橋を渡る。

---

## 5. CLEAR

**PERFECT FIT!**

次の問題へ。

---

# MVPの判定方式

初版では、

**物体認識をしない。**

ここが重要。

必要なのは、

> 指定されたシルエット領域が、背景とは異なる何かで十分覆われている

くらいの判定。

---

# 判定案 A
## ガイド領域の画像差分

問題開始時に、

**背景画像を1枚取得。**

その後、

ガイド領域内に何か新しい物体が入る。

開始画像との差分量を見る。

差分が一定以上なら、

**OBJECT PRESENT**

---

# 判定案 B
## 輪郭量

ガイド内部に、

十分なエッジが存在するかを見る。

橋なら、

細長い輪郭が横方向へ存在することを確認。

---

# 判定案 C
## 手動LOCK + 緩い自動採点

MVPとして最も安全。

プレイヤーが、

**「合った！」**

と思ったところでLOCK。

その瞬間の画像から、

- ガイド被覆率
- はみ出し量
- 角度差

だけ採点する。

厳密な正解判定ではなく、

**GOOD / GREAT / PERFECT**

程度にする。

---

# 推奨MVP

まずは **C**。

FALSE BRIDGEで知りたいのは画像認識精度ではなく、

**合わせる行為が楽しいか**

だから。

AI認識との戦争は後回し。

# 重要なデザイン原則

## 1. 「これを使え」と指定しない

悪い：

**FIND A PENCIL**

良い：

**MAKE A BRIDGE**

プレイヤー自身が、

「これ使えるんじゃない？」

を発見することが遊び。

---

## 2. 正解物体は存在しない

鉛筆でもいい。

箸でもいい。

指でもいい。

細長ければ成立する。

つまり問題データは、

**物体名ではなく形状条件**

を持つ。

---

## 3. 判定は甘く

現実空間なので、

1〜2ピクセルの正確さなど不要。

だいたい合えば成功。

むしろ、

**本人には合って見えるのにゲームには不正解**

が最悪。

---

## 4. スマホを動かすことも操作

机上の物だけ動かすゲームにしない。

物体が大きすぎるなら、

スマホを離す。

小さすぎるなら、

近づく。

角度が違えば、

スマホを傾ける。

**カメラ位置そのものがパズル操作。**

---

# 画面UI

極力少なくする。

上部：

**STAGE 01 / BRIDGE**

中央：

ARガイド

下部：

**LOCK**

補助表示：

**MOVE / ROTATE / CLOSER / FARTHER**

ただし常時出さず、

一定時間詰まった時だけ表示。

---

# ALIGN FEEDBACK

ガイド：

白い点線。

少し合う：

**黄色系反応**

かなり合う：

**ガイドが収束**

成功圏：

**LOCK READY**

重要なのは、

**数値を見ながら位置合わせするUIにしないこと。**

ゲームではなく測量になってしまう。

---

# SCORE

MVPではスコア不要でもよい。

入れるなら、

### FIT
形状一致度

### TIME
完成時間

だけ。

初期プレイテストでは、

**クリアできたか / 面白かったか**

を優先する。

# 撮影環境問題

FALSE BRIDGE最大の敵。

**背景が複雑すぎる問題。**

対策：

問題開始時に、

**1秒静止してください**

と表示して背景基準画像を取得。

その後に物を入れてもらう。

---

# 暗所問題

画像差分が取りにくい場合、

自動判定を諦めて、

**LOCK後の自己判定**

も選択肢。

たとえば、

**LOOK GOOD?**

YES / RETRY

でもいい。

EXP段階では、

ゲームの芯を潰してまでCVを完璧にしない。

最低5人または5セッション。

1. Stage 001で何をすべきか理解できるか

特に、

**2 / 4 / 5 / 8**

が通れば成功。

# 最終的な可能性

FALSE BRIDGEが成立すると、

問題は、

**「現実世界に何があるか」**

ではなく、

**「それを何に見立てられるか」**

になる。

これは普通のARとは少し違う。

ARが、

**現実の上にゲームを置く**

ものだとしたら、

FALSE BRIDGEは、

**現実そのものをゲーム素材として読み替える。**

この違いが、このEXPの金脈。
