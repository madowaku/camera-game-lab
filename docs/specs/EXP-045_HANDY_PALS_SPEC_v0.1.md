# EXP-045 HANDY PALS
## Camera Game Lab Prototype Specification v0.1

### 1. コンセプト

**両手をカメラにかざすと、手の上にかわいい人形が現れる。\
手を動かすだけで、2人の人形が一緒に踊ってくれる。**

プレイヤーに正確な振り付けを要求しない。

雑な手の動きを、

**「かわいいダンス」へ自動翻訳する。**

このゲームの成功条件は、

> 手を出した瞬間に「かわいい！」と思えること。

---

# 2. 一言説明

**両手が、ふたりのダンサーになる。**

英語：

**Your hands become two tiny dancers.**

---

# 3. ジャンル

- インカメラゲーム
- カジュアル
- ダンス
- キャラクタートイ
- 動画映え
- 非競技型

---

# 4. 想定プレイ時間

**20〜30秒**

起動から終了まで1分以内。

繰り返し遊ぶことを前提とする。

---

# 5. コア体験

1. カメラの前に両手を出す
2. 左右の手を認識
3. それぞれにキャラクターが出現
4. 音楽スタート
5. 手を自由に動かす
6. 動きがダンスへ変換される
7. ときどき2体が掛け合う
8. 最後にFINAL POSE
9. 記念写真／短いリプレイ

---

# 6. 最重要デザイン原則

## 「正確に追従させない」

プレイヤーの手の動きを、そのまま人形へ反映しない。

入力はあくまで、

**ダンスアニメーションを選ぶためのきっかけ**

として扱う。

たとえば手を30cm上げた場合、

人形を30cm移動させるのではなく、

- ジャンプ
- 万歳
- 片足ポーズ
- くるっと着地

などへ変換する。

入力が多少不正確でも問題ない。

---

# 7. キャラクター表示方式

## MVP案

各手のひら付近に1体ずつ表示。

### 左手
PLAYER A

### 右手
PLAYER B

キャラクターは約1.5〜2頭身。

大きめの頭。

短い手足。

弾力のある動き。

完全な物理追従ではなく、

**100〜250ms程度の柔らかな遅延**

を持たせる。

これにより、

- ぷるぷるする
- 引っ張られる
- 慌てて付いてくる

などの生命感を出す。

# 9. 基本入力

精密な指認識は極力使用しない。

使用する情報：

- 左手中心座標
- 右手中心座標
- 高さ
- 左右移動量
- 移動速度
- 左右の距離
- 手の向き
- 手の開閉
- 手が画面内に存在するか

---

# 10. 入力 → ダンス変換

| プレイヤー入力 | キャラクター |
|---|---|
| 手を左右へ振る | 横ステップ |
| 手を上げる | ジャンプ |
| 手を下げる | しゃがみ |
| 円を描く | ターン |
| 素早く動かす | ダッシュステップ |
| 指を開く | キラキラポーズ |
| 両手を近づける | ハイタッチ |
| 両手をさらに近づける | ハグ |
| 両手を離す | 左右へジャンプ |
| 手を突然消す | キャラクターが転ぶ／探す |
| 動かさない | アイドルダンス |

判定には広い許容幅を持たせる。

# 11. アイドル動作

プレイヤーが何もしなくても、

キャラクターは静止しない。

ランダムに、

- 足踏み
- 体を揺らす
- 相手を見る
- 手を振る
- 頭をかく
- くしゃみ
- ウインク
- 周囲を見る
- 相手の真似をする

などを行う。

目的：

**両手を置いているだけでも画面がかわいい状態を維持する。**

# 12. キャラクター性格

左右を完全同期させない。

### LEFT
元気。

反応が速い。

大きく動く。

### RIGHT
少しおっとり。

反応が100〜200ms遅い。

小さなリアクションが多い。

このズレによって掛け合い感を出す。

# 20. 音楽設計

明るいポップ系。

BPM：

**110〜130程度**

入力に完全同期するリズムゲームにはしない。

キャラクターのアニメーション開始位置だけ、

ビート近辺へスナップする。

これにより、

適当な入力でも

**なんとなく音楽に合っている**

ように感じさせる。

# 23. 認識失敗時

片手をロストした場合、

人形を即消去しない。

約500〜800ms待つ。

その間、

キャラクターが、

「おっとっと！」

のようにバランスを崩す。

再認識したら自然に復帰。

長時間消えた場合、

キャラクターが画面外を探す。

認識ミスを可能な限り

**キャラクター演出として吸収する。**

# 27. Human Playtest 判定

プレイヤー5人程度で確認。

最重要観察項目：

1. 人形登場時に反応があるか
2. 説明なしで手を動かし始めるか
3. 意図的にいろいろな動きを試すか
4. 両手を近づける行動を自然にするか
5. ハイタッチに気づくか
6. キャラクターを見て笑うか
7. 認識ミスを不快に感じるか
8. もう一回遊ぶか
9. 別キャラを試したがるか
10. 動画を撮りたくなるか

---

# 28. 最重要KPI

数値スコアより、

### 「もう一回」

が出るか。

さらに、

### 「このキャラでもやってみたい」

が出れば成功。

最高評価：

### 「これ動画撮りたい」

---

# 29. 成功条件

MVP成功ライン：

**初見プレイヤーが説明を読まずに両手を出し、10秒以内にキャラクターを意図的に動かし始める。**

強い成功：

**プレイヤーが自発的に変な動きを試し始める。**

理想：

**プレイヤー自身が新しい遊び方を発見する。**

---

# 30. このEXPで検証する仮説

## H1
精密入力がなくても、かわいいキャラクター反応だけでカメラゲームは成立する。

## H2
「操作する」より「反応を見る」楽しさの方が強い可能性がある。

## H3
認識誤差をキャラクターアニメーションへ吸収できる。

## H4
スコアなしでも短時間リプレイ性を作れる。

## H5
プレイそのものがSNS動画コンテンツになる。

# 31. EXP-045の核心

HANDY PALSは、

**ダンスゲームではない。**

**両手を使って、かわいい生き物を飼う30秒間のおもちゃ。**

操作の正確さではなく、

「動かしたら何をしてくれるんだろう？」

という好奇心で手を動かさせる。

最初のゴールはただひとつ。
