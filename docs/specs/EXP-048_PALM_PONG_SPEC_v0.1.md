## 1. 企画の合意と実験の目的

ユーザー発案の「卓球ゲーム」を、二人の片手に大きなラケットを付け、同じスマホのインカメラでラリーを続ける遊びとしてEXP化する。前の会話で提案した協力ラリーをv0.1の入口とする。

横画面、30秒、位置だけで返球、当たった場所による返球角度、ミス後の即再サーブは今回の設計仮説。数値は実機調整用の初期値であり、認識精度や面白さの実測結果ではない。

| 確かめること | 成功の観察 | 不成立の兆候 |
|---|---|---|
| 初見の分かりやすさ | 手のラケットを球の前へ出すだけで返せる | 振り方や指の形を何度も説明する |
| 気持ちいい返球 | 見えているラケットに当たり、「ぽん」と次へ飛ぶ | 見た目では当たるのにすり抜ける |
| 二人の協力 | 「次そっち」「あと一回」が自然に出る | 一人だけで両側を操作する |
| ラリーの変化 | 次の高さを読んで、小さく手を動かす | 二手を置いたまま30秒間続く |
| 見て伝わる遊び | 5秒の映像で「二人で卓球」と説明できる | 球・ラケット・手の関係が見えない |

### 方式の比較

| 方式 | 得られる体験 | v0.1の判断 |
|---|---|---|
| **位置で返す協力ラリー** | 初見で返せる。ミスも笑って再挑戦できる | 採用 |
| 手を振って打つ対戦卓球 | 強打・駆け引きを作れる | 手速度と遅延の検証後に検討 |
| 奥行き・ラケット角度を使う卓球 | 現実の卓球に近い操作 | 初回原型には入れない |

## 3. 遊びの流れ

1. スマホを横に固定し、二人が並ぶ。各自の片手を胸〜顔の高さで見せる。
2. 左の手にミント、右の手にコーラルのラケットが付く。手の位置に重なって追従する。
3. 二手がそれぞれの色の領域で安定するとSTARTを押せる。3・2・1で開始。
4. 最初の球は中央から左へ。落ち着いてラケットを球の前へ出す。
5. 当たると相手側へ返る。次の人は球の高さを見て受ける。以後、左右交互に返す。
6. ラリーが続くほど球が少し速くなり、返球音が小さなメロディになる。
7. 取り逃しても「もう一球！」ですぐ再サーブ。30秒で最長ラリーを表示する。

準備の説明は**「ふたりで並ぶ」「手を出す」「球の前へ」**の3つ。ピンチ、握る、指の形、掌の向き、手を振る速さは操作条件にしない。手が追跡できればラケットを表示する。

## 4. 画面と操作領域

### 横画面を採用する理由

左右に並ぶ二人と、左右へ往復する球を同じ構図で見せる。顔と手を大きく映しつつ、球が相手へ向かう意味を分かりやすくする。HAND HOPの縦画面仕様はPALM PONGへ引き継がない。

物理の基準領域は`W=16`、`H=9`の固定した仮想単位。画面の安全領域内にアスペクト比を保って配置し、CSSピクセルへの変換は描画で行う。球の円・角度・速さを画面寸法や回転で変えない。

基準確認は800×360、1280×720。縦の360×800、720×1280では入口・結果が読めるようにし、カメラ開始前に「スマホを横にして、ふたりで並ぼう」を表示する。練習は同じ16:9領域で縦画面でも試せる。

| 層 | 見せるもの |
|---|---|
| 背面 | 二人のミラー映像。顔は球や文字で覆い続けない |
| コート | 半透明の明るい卓球台、中央の細いネット風の線、上下の跳ね返る縁 |
| ゲーム | 黄色い球、短い軌跡、二色の大きなラケット、次に受ける目安 |
| HUD | 中央に現在ラリー、隅に残り時間・一時停止 |
| 案内 | 必要な時だけ「左の手を見せて」「自分の色へ」など |

背景色はクリーム、台は淡いミント、相手側は淡いコーラル。色だけに頼らず左ラケットに一つ、右に二つの丸印を付ける。球は太い白縁で人物の服から分離する。中央線は飾りで、球との衝突判定は持たない。上下の縁は実際に反射するため、見える線として描く。

### 手とラケット

手のひら中心はランドマーク`0,5,9,13,17`の平均。ミラー・`object-fit: cover`の切り抜き・ゲーム領域への変換を映像と一致させ、反転を二重に適用しない。

- 左のラケット中心の有効範囲：`x=0.10W〜0.42W`。
- 右の有効範囲：`x=0.58W〜0.90W`。
- 両側の有効範囲：`y=0.17H〜0.83H`。
- ラケットは縦向きで、高さ`0.24H`、厚み`0.024W`。球は半径`0.013W`。
- X・Yとも手に追従する。手のXを無視して固定したレーンへ移動させない。
- 中心が自分の範囲から出たラケットは輪郭だけにし、返球判定を無効にする。「自分の色へ」と短く示す。画面端へ座標を押し込んで有効なラケットを残さない。
- 片手が相手側へ移動しても相手のラケットには変わらない。二手の持ち主は移動履歴で保持する。

## 5. 球・返球・受ける目安

### 物理と初期値

| 項目 | 初期値・ルール |
|---|---|
| 有効プレイ時間 | 30秒。ミス後の再サーブ時間も含む |
| 固定ステップ | `1/120秒`。描画・推論頻度から独立 |
| 最初の球速 | `0.50W/秒` |
| 返球後の球速 | 現在ラリーを`n`として`min(0.78, 0.50 + 0.014n)W/秒` |
| 返球角度 | 横向きから最大上下42度 |
| 上下の縁 | 球中心が`r`／`H-r`に達すると上下速度反転 |
| ミス | 球中心が左右の画面外`-r`／`W+r`へ出る |
| 再サーブ | ミスから650ms後。中央から次の担当へ、初期球速で送る |

物理ではX・Yに同じ仮想単位を使う。角度計算で正規化X・Yの差をそのまま混ぜない。球速はベクトルの大きさであり、対角移動で勝手に速くしない。

最初の球は`x=0.50W,y=0.50H`から左へ水平に送る。ミス後は取り逃した側へ送るので、直前の受け方をすぐ試せる。再サーブ中は中央の球と行き先を見せ、次の球を突然出現させない。

### どこに当てるか

接触時の高さの差を`u=(ballY-paddleY)/(paddleHalfHeight+r)`で求め、`-1〜1`に収める。上端なら上向き、下端なら下向き、中央付近ならほぼ水平に返る。

手を置いたままラリーが続くのを防ぐため、返球直後だけ、小さな角度差を加える。初期列は`[+8,-10,+12,-8,+10,-12]度`を各ラリーの返球順で繰り返す。

`theta = clamp(36度 × u + 角度差, -42度, +42度)`。

左で返した後は`vx=+speed*cos(theta)`、右なら`vx=-speed*cos(theta)`。どちらも`vy=speed*sin(theta)`で、画面下向きを正とする。角度差の列はミスで最初へ戻す。球は飛んでいる間に行き先を変えない。角度差はルール説明を増やさず、実際の軌道と受ける目安で伝える。

この値で静止した二手のラリーが続きすぎる、または初見で急に難しくなる場合は、角度差と球速を実機記録から調整する。ラケットを振る速さを返球条件に追加しない。

### 連続衝突判定

返球対象は`nextReceiver`の一枚だけ。左は左向きの球、右は右向きの球を、中央側の面で受ける。返した瞬間に`nextReceiver`を反対側へ切り替える。

1. 直前・現在の球と、同じ区間のラケット位置から、中央側の面へ球が近づいて横切る時刻を求める。
2. 接触時点で縦方向がラケット半高＋球半径に重なることを確認する。
3. 球をラケットの中央側の接触面へ置き、上記の角度・速度で反対へ返す。
4. 一度だけ返球イベントを発行し、残りのステップ時間を新しい速度で進める。

ラケットを上・下からかぶせた接触、背面接触、球から離れる動き、範囲外のラケット、座標の不連続な飛びは返球にしない。ラケット移動自体の交差は連続した信頼できる座標に限り扱い、手速度を威力へ加算しない。

上下の縁・ラケット・左右のミス境界は同じ時間軸で最早の接触から処理する。同時刻なら上下反射→ラケット→ミスの順とする。タイムアップが同時なら終了を優先。球の離隔と`nextReceiver`により一接触の二重加点を防ぐ。

### 初見を助けるガイド

次に受ける側を薄く点灯し、球から最大0.8秒先までの短い点線を出す。現在の受け手のラケットXで球が通る高さを、小さな輪で示す。上下反射を含め、ラケットがまだ返していない先の球は予測しない。

目安は当たり判定を持たない。球の軌跡を隠すほど明るくしない。通常は表示し、慣れた人は開始前の設定で消せる。ガイド有無で記録は分けず、共有へ余分な条件文を増やさない。

## 6. 認識の安定性・準備・復帰

### 二手の割り当て

開始前、画面左の手をP1、右をP2へ割り当てる。以後は位置・速度の履歴で対応し、毎フレームX順で並べ直さない。handednessは補助情報で、左右分類の変化だけで色を交換しない。

必要なのは二つの手であり、二人の顔認識は行わない。一人の両手でも動作確認できるが、製品での二人参加を自動証明する仕組みではない。三本目が入っても既存二枠を優先する。対応が曖昧なら追跡停止へ進み、相手のラケットを一時的に貸さない。

平滑化の初期時定数は60ms。描画と判定に同じ平滑化座標を使う。新しい信頼できる推論座標の間は物理入力を補間するが、ロストや飛びの区間を連続移動として埋めない。

初期の座標飛び判定は、100ms以内の更新で手中心が`0.25W`以上移動した場合。その枠を追跡不確実とする。実際の素早い動作を頻繁に止める場合は実機記録から調整する。

### 開始・ロスト

- 準備では二つの手のガイドを出す。二手が有効範囲で500ms安定するとSTARTを有効にする。
- モデル待ち、カメラ待ち、左手待ち、右手待ちは短い別文言で表示する。
- ロストから150ms以内は最後の信頼できるラケット位置を保持する。
- ロスト中に、次の受け手への接触またはミスが起きる予定なら、その直前で即停止する。古い座標で成功・失敗を確定しない。150msを超えた場合は接触予定に関係なく停止する。
- 停止は球・30秒・650ms再サーブをすべて止める。手ロストをプレイヤーのミスや加点に変えない。
- 復帰した二手が500ms安定すると「1」で再開。ラリー、球速、次の担当、残り時間を引き継ぐ。
- 復帰前後の座標を衝突用の移動として結ばない。球とラケットが重なった場合は停止中に中央側の接触面へ球を押し戻し、加点せず速度を保持してから再開する。
- 10秒以上戻らない場合は「位置を合わせ直す」「カメラなしで練習」「終了」を表示する。練習へ移った場合は別のラウンドとして開始し、途中のカメラ記録を移さない。

自分の操作領域から出た、追跡自体は正常な手はロストと区別する。領域外のラケットは無効で、球と時間は進む。実写の切り抜きで画面外へ消えた手はロスト扱いにし、端へ固定しない。

ユーザーの一時停止、タブ非表示、画面回転でも停止。横へ戻した後は表示変換と手を合わせ直す。停止時間をまとめて物理へ投入しない。処理が詰まって200ms超の未処理時間が生じた場合は処理待ち停止にし、その区間をタイマーだけ進めない。

## 7. ラリー・結果・再挑戦

### 数えるもの

「ラリー1」は一回の有効なラケット返球。左右一往復は2ラリー。サーブ、上下の反射、予測ガイドとの接触は数えない。

| 記録 | 定義 |
|---|---|
| 現在ラリー | 今の一球での連続した有効返球数。ミスで0へ戻す |
| 最長ラリー | ラウンド中の現在ラリーの最大値。主記録 |
| 合計返球 | 30秒内の有効返球の総数 |
| P1／P2返球数 | 二人それぞれの担当回数 |
| ミス回数 | 左右のミス境界へ出た回数。ロストでは増やさない |

結果の主役は**「ふたりで 18ラリー！」**。二つのラケットが球を挟む明るいカードにし、合計返球・参加回数は小さく置く。ミスを大きな失敗評価として掲げない。

主ボタン「もう一回、つなごう」、次に「友達に挑戦状」、控えめに「ほかのゲーム」。共有例：「ふたりの手で18ラリー！君たちは何回つなげる？ PALM PONG」＋直接ゲームへのリンク。

カメラなし練習は「練習」を表示し、カメラの自己ベストへ混ぜない。設定・最長ラリー・集計だけを保存し、モデル由来の手座標や映像を記録しない。

時間切れは球やサーブ演出の完了を待たず集計を固定する。最後に約350msの挨拶を描いて結果へ進む間も、新しい返球・ミスを加算しない。再挑戦で球、ラリー、角度差列、演出、タイマーを初期化し、前回のイベントを持ち越さない。

## 8. 返球の気持ちよさと見せ場

| タイミング | 演出 |
|---|---|
| 接触0〜40ms | 球がむにゅっと横につぶれ、ラケットに小さな輪 |
| 40〜140ms | 球がぽんと戻り、短い色の軌跡。「ぽん」の音 |
| 5・10・20ラリー | 数字が一度ふくらむ、短い星の輪、控えめな祝福音 |
| ミス | 球がふわっと画面外へ。「もう一球！」を短く表示 |
| 終了 | 二つのラケットが小さくおじぎし、最長ラリーが結果へ残る |

つぶれは見た目のアニメーションで、物理の返球を待たせない。顔・カメラ映像・コートを揺らさず、球とラケットに弾力を集中させる。スロー演出はv0.1に入れない。

返球音はペンタトニックの短音を順に使い、左右で音色を少し変える。テンポが上がるほど自然に音が連なり、無音でも接触・次の担当・ラリーが分かる。音は開始操作後に有効にする。

15秒の見せ場は「二人の手がラケットになる→ゆっくり二往復→少し速くなる→ぎりぎり返す→最長ラリー」。宣伝コピーは「あなたたち、何回つなげる？」。v0.1の共有はテキストとリンクまで。将来のCREATOR MODE向けに返球・節目・端でのキャッチをイベントで拾える構造にする。

## 9. 状態・練習・終了処理

| 状態 | 主な遷移 | 球・30秒 |
|---|---|---|
| ENTRY | カメラ準備／練習 | 停止 |
| CALIBRATION | 二手が安定→START→COUNTDOWN | 停止 |
| COUNTDOWN | PLAYING | 停止。終了時を30秒の起点にする |
| PLAYING | SERVE_WAIT／PAUSED／ROUND_END | 進行 |
| SERVE_WAIT | PLAYING／PAUSED／ROUND_END | 球停止、650msと30秒は進行 |
| PAUSED | 復帰確認後、元の状態 | 球・30秒・再サーブ停止 |
| ROUND_END | 約350ms後にRESULT | 記録固定、表示演出のみ |
| RESULT | 再挑戦／共有／離脱 | 停止 |

練習は二点のマルチタッチでラケットを操作する。左右の`pointerId`を開始時に固定し、片方の指を離しても他方へ操作を移さない。PCはP1=WASD、P2=矢印キー。カメラ版と同じ入力領域・物理・返球・結果を通す。カメラ権限・モデル・マイクを不要にする。

v0.1はインカメラの二手だけを追跡する。マイク・録画・写真保存は使わない。映像・手座標は端末内で処理し、外部送信しない。初回モデル取得について準備画面で案内する。

離脱、権限拒否、開始取消では推論、カメラトラック、音、イベント購読を解放する。再挑戦は進行中のカメラセッションを再利用できるが、推論ループを追加起動しない。練習へ切り替える時はカメラを止める。

## 10. 既存実装への接続と作業項目

### 確認済みと提案を分ける

今回mainで本文を確認したファイル：

- `src/platform/experiments.js`：ゲームID、`players: 2`、`orientation: "landscape"`、`input: ["HAND"]`、`duration: 30`、lazy loader、JA／EN文言を追加する接続先。現時点でPALM PONGは未登録。
- `src/handy/tracking.js`：二手の履歴対応、手の中心、ミラー、切り抜きの実装例。現在の`handToStage`はキャラクター用にX・Yを収めるため、その座標制限をPALM PONGへ流用しない。handednessの不一致に大きな対応コストがあるため、左右分類だけで持ち主を切り替えない契約も別途確認する。

HAND HOP仕様で既存の再利用先として確認された`src/input/handyPalsInput.js`と`src/input/bodyInput.js`は、今回本文の再確認をしていない。実装開始時に最新の二手モデル設定・開始／停止を読む。既存DUOの二顔入力と同じものだと扱わない。

新設候補は`src/palmPong/{core,view,presentation}.js`と`src/input/palmPongInput.js`。提案パスであり、これらのファイルが既に存在するとは主張しない。

- core：二枚の処理済みラケット座標から球・角度・交互返球・30秒・記録を更新する。
- input：二手対応、信頼性、映像変換、ロストを扱う。
- view：入口、準備、描画、結果、練習、JA／ENを扱う。
- presentation：短い返球演出と共有文を扱う。録画を必須にしない。

### 実装へ渡す作業項目

これはEXPの範囲と完了条件。実行時は最新の構成を確認して具体的な変更計画へ落とす。

| 順 | 作業 | 完了条件 |
|---|---|---|
| 1 | 入口・横画面・練習 | deep linkから起動し、二点でラケットを動かせる |
| 2 | 球・縁・返球のコア | 低FPSでも見た目の接触で一度だけ返せる |
| 3 | 角度・球速・ガイド | 中央と端で軌道が変わり、次の高さを読める |
| 4 | 二手追跡・準備・復帰 | 色が入れ替わらず、曖昧な座標で加点・ミスを作らない |
| 5 | 30秒・再サーブ・結果 | ミス後650msで続行し、最長ラリーを正しく残す |
| 6 | 音・弾力・節目 | 反応を遅らせずに接触感が出る |
| 7 | 再挑戦・共有・JA／EN・離脱 | 練習の記録を区別し、カメラ・音・古い演出が残らない |
| 8 | 自動QA・二人実機評価 | 判定と状態を確認し、以下の人による観察を記録する |

イベントの最低限：`SERVE`、`RETURN`、`WALL_BOUNCE`、`RALLY_MILESTONE`、`MISS`、`TRACK_LOST`、`TRACK_RETURNED`、`ROUND_END`。ゲーム時刻、ラウンドID、必要に応じてP1／P2を付け、再処理を防ぐ。端の返球は`RETURN`の接触位置情報で判断し、判定を別に重複実装しない。

## 11. 検証とHuman Playtest

### 自動QAで確かめる失敗条件

- 球が一ステップでラケットを越えても、移動する前面との接触を見落とさない。
- 高速の同一接触、上下反射と返球の同時接触で二重加点・壁への吸着を起こさない。
- 上下からの接触、背面、同じ側への連続返球、範囲外、座標飛びでは加点しない。
- 左右の返球角度、速度の上限、角度差列、ミス後の初期化が定義どおり。
- 球が飛んでいる間に入力やガイドが勝手に球の軌道を変えない。
- ミラー・cover・ゲーム領域の変換が、手・ラケット・判定で一致する。
- 手の交差、三本目、短いロストで色や担当回数を交換しない。
- 追跡が曖昧な時の接触・ミスで、古い手位置による成功・失敗を確定しない。
- ロスト、非表示、回転、処理待ちの時間を復帰時にまとめて消費しない。
- 30秒終了と返球・ミスが同時なら終了を優先し、結果後に記録が変わらない。
- 二点タッチの片方を離しても残った指が二枚を動かさない。
- 再挑戦・練習切替・離脱・開始取消でカメラ、音、購読、演出を重複させない。
- 800×360、1280×720で球の形・角度・物理速度が変わらず、縦画面の入口・結果が読める。

### 二人で5ラウンド

第一基準機はAndroid A401OPのChrome。二人で各30秒。iOSや別端末は確認まで対応確認済みとは書かない。

| 回 | 条件 | 観察 |
|---|---|---|
| 1 | 初見・室内 | 追加説明なしで手を出し、10秒以内に4ラリーできるか |
| 2 | 同じ二人で再挑戦 | 8ラリー以上を一度達成するか、声掛けや先読みが出るか |
| 3 | 意図的に中央・端へ当てる | 軌道の違いを理解するか。画面と判定が一致するか |
| 4 | 片手を外す・少し交差する | ミスを押し付けず停止できるか。色とラリーが保たれるか |
| 5 | 距離・画角を調整 | 胸〜顔の範囲の小さな動きで遊べるか。腕を大きく振る必要がないか |

記録は最長／合計ラリー、二人の返球数、ミス、見た目は当たったのに返せなかった回数、ロスト停止時間、推論FPS、再挑戦意欲、観客が遊びを言い表せるか。

別の短い対照試験として、二手を静止して置く。中央に置いたまま10ラリー以上安定して続くなら、放置で成立しすぎていないか角度差を見直す。一人の両手でできることを不具合にはしない。

仮の面白さゲート：5回中4回で両者が3回以上返球、2回目までに8ラリーを一度達成、追加の振り方説明が不要、5秒の映像で観客が協力卓球だと分かる。見た目の接触に対するすり抜けは5回合計で2回以下を目安に原因を追う。少人数の探索評価であり、製品全体の評価とは区別する。

初見の返球が厳しい場合は、球速→ラケットの高さ→ガイド→追跡遅延の順に確認する。認識の不安定さを新ルールで補わない。

## 12. v0.1の範囲と次の拡張

v0.1：横画面、二手ラケット、協力30秒、交互返球、接触位置による角度、緩い速度上昇、上下反射、再サーブ、最長ラリー、練習、再挑戦、テキスト／リンク共有、JA／EN。

実機評価後の候補：対戦モード、手速度による強打、目標へ返すチャレンジ、CREATOR MODE、ラリーの長さによるコート演出、時間制限なし。ショップ・アイテム・スキル選択は初回原型へ入れない。

### Codexへ渡す要約

> camera-game-labへEXP-048 PALM PONGを追加してください。二人の片手に大きなラケットを付け、横画面で30秒の協力ラリーを続けます。手の中心位置だけで操作し、ピンチ・指の形・掌の角度・振る速さを条件にしません。中央側の前面で球を交互に返し、接触位置で角度、連続返球数で速さを変えます。小さな角度差と実際の受ける目安で、静止した手だけの放置ラリーを避けます。ミス後650msで再サーブ、手ロストは球と時間を止めます。カメラなしの二点練習で衝突コアを確かめ、二手追跡・準備・復帰・結果・共有・JA／ENを接続してください。既存のHANDY PALSやDUO入力の挙動を維持し、自動QAと二人の実機評価を分けて報告してください。
